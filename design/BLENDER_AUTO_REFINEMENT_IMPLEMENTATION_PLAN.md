# Blender 自动精修实施计划

## 1. 总体目标

将现有“图片生成基础 GLB”的单阶段流程升级为两个独立阶段：

1. 基础生成：输入图片 → 基线 GLB → 四视图 → 用户确认并锁定基线版本。
2. 自动精修：锁定的基线 GLB → Blender 自动精修 → 新版本 GLB → 质量门禁 → 用户验收。

自动精修必须真实调用 Blender 后台执行。每次任务创建新版本，不覆盖源版本；任务必须提供实时日志、阶段状态、产物和质量报告，不得将未执行能力标记为通过。

## 2. V1 交付范围

V1 完成以下可闭环流程：

> 基线 GLB → 几何清理 → 自动 UV → 基础 PBR 材质 → Web 优化 → 四视图渲染 → 质量报告 → 新版本 GLB

### 2.1 Blender 自动精修任务

- 新增独立 Blender 自动精修脚本和后端适配器。
- 通过现有任务队列在后台执行，支持实时日志、取消与失败处理。
- 输入必须是已存在且锁定的源版本。
- 输出必须创建新版本，并记录父子版本关系。
- 保存精修配置快照、模块结果、统计信息和所有产物。

### 2.2 自动几何修复

- 应用对象变换并统一尺度。
- 清理重复顶点、松散几何和退化面。
- 重算法线并执行网格有效性检查。
- 只自动填补满足安全阈值的小孔洞，避免盲目封闭大型开口。
- 支持保守的平滑处理。
- 根据目标三角面范围执行可选减面。
- 对比处理前后包围盒、体积、面数与非流形统计，防止明显破坏轮廓。

### 2.3 自动 UV

- 检查现有 UV 是否存在且可用，合格时优先保留。
- UV 缺失或不合格时自动重新展开。
- V1 使用 Blender Smart UV Project，并配置安全的岛间距。
- 自动排列 UV 岛，检测越界、空 UV 和明显重叠。
- 在报告中记录 UV 来源、岛数量、利用率和检查结果。
- 后续版本再增加适用于复杂角色的自动切缝策略。

### 2.4 PBR 材质自动生成

V1 自动创建并导出以下通道：

- Base Color
- Roughness
- Metallic
- Normal
- Ambient Occlusion（AO）

执行要求：

- 自动创建 Blender Principled BSDF 节点和贴图连接。
- 支持将正面参考图投射为 Base Color 证据。
- 不可见区域使用明确标记的自动推断或用户选择的材质模板。
- 自动烘焙、保存并打包贴图，最终写入或关联到 GLB。
- 检查贴图缺失、错误色彩空间和无效材质引用。
- 单张图片无法证实的背面颜色、金属度和粗糙度必须标记为“自动推断，待验收”。

### 2.5 Web 优化与渲染

- 根据用户配置控制目标三角面范围、贴图分辨率和最大 GLB 大小。
- 导出浏览器兼容 GLB，并验证文件可解析。
- 自动生成正面、左前 3/4、侧面和背面四张验收图。
- 保留处理前后的关键统计，供界面比较。

## 3. 自动质量门禁

精修任务完成前必须检查：

- 输出 GLB 存在、非空且可以正常解析。
- 模型包含有效网格，没有新增严重几何错误。
- 非流形、退化面和法线问题相较源版本没有恶化。
- 三角面数处于配置范围内，或明确记录偏差原因。
- UV 存在且没有越界、空数据或不可接受的重叠。
- PBR 材质节点和必要贴图完整。
- GLB 文件大小符合 Web 目标，或明确标记超限。
- 包围盒或体积变化没有超过安全阈值。
- 四个视角均渲染成功。

任何必需门禁未通过时，任务不得显示为成功；界面应展示具体失败项和日志。

## 4. 网站与 API 调整

### 4.1 能力状态

- 几何修复：自动。
- 自动 UV：自动。
- PBR 材质：自动生成、用户验收。
- Web 优化：自动。
- 视觉质量评审：等待用户确认。
- 身份特征精修：暂时保留人工或未配置。
- 分件：暂时保留人工或实验性。
- 骨骼绑定：暂时保留实验性或未配置。

### 4.2 精修配置页

- 增加几何修复强度、UV 策略、贴图分辨率、材质模板、目标面数和最大 GLB 大小配置。
- 清晰区分“自动执行”“自动推断、待验收”“人工”和“未配置”。
- 显示源版本并说明源版本不会被覆盖。

### 4.3 精修监控页

- 展示真实 Blender 阶段、进度和实时日志。
- 展示源版本、输出版本和版本关系。
- 展示各模块的真实结果，不使用预设成功状态。
- 完成后提供新 GLB、PBR 贴图、四视图和质量报告下载或预览。
- 自动阶段完成但仍需视觉确认时，状态应为“等待验收”，而不是“等待技术人员处理”。

### 4.4 数据模型建议

- 为精修产物增加独立关联表，避免借用基础生成任务的产物关系。
- 为版本增加父版本关系，可使用 `version_links` 表或等价字段。
- 输出版本记录源版本、精修任务、配置快照和实际执行的 Blender 版本。

## 5. 验收标准

V1 视为完成必须满足：

1. 用户能从已确认的基线版本创建自动精修任务。
2. 后端真实启动 Blender，执行几何清理、UV、PBR、优化和四视图渲染。
3. 任务产生独立的新版本 GLB，原基线文件和数据库记录保持不变。
4. 新 GLB 能在网站 Three.js 预览器中正常加载并显示材质。
5. 监控页能看到真实日志、各阶段结果、输入输出版本和质量报告。
6. 自动 UV 与 PBR 结果能够被检查，推断内容有明确标记。
7. 门禁失败时任务准确失败或进入需处理状态，不得伪报通过。
8. 自动化测试覆盖任务创建、版本派生、成功、失败和取消路径。
9. 使用实际 GLB 完成一次 Blender 本地冒烟测试。
10. 前端构建和后端测试全部通过，重启服务并刷新网站完成验证。

## 6. 暂不纳入 V1

- 单张正面图片下的精准背面还原。
- 专业级角色重拓扑。
- 完全准确的物理材质识别。
- 高质量自动分件和语义命名。
- 生产级自动骨骼、蒙皮和动画。
- AI 驱动的局部雕刻与身份特征重建。

这些能力可在 V1 稳定后依次扩展为参考图智能投射、AI 材质识别、背面补全、局部身份精修、自动分件与自动绑定。

## 7. 新任务执行指令

新任务可直接使用以下目标：

> 按 `design/BLENDER_AUTO_REFINEMENT_IMPLEMENTATION_PLAN.md` 落地 Blender 自动精修 V1。持续执行到全部验收标准完成；遇到无法通过代码、环境检查或安全的本地替代方案解决的实际阻断时，停止并说明准确卡点。不得用模拟状态代替 Blender 的真实执行结果。
