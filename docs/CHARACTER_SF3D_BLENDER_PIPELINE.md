# 单图人物 SF3D → Blender → Three.js 流程规范

版本：1.0  
状态：经 `Field Commander` 首轮测试验证，可用于下一个模型  
目标：从人物三视图素材中选择正面图生成连续网格，保留 SF3D 的整体形体，在 Blender 中局部修形，最后形成可验证的网页 GLB。

## 1. 能力边界

- Stable Fast 3D（SF3D）是单图重建模型。输入三视图拼图不会让它严格融合三个视角，反而容易把多个人形识别为一个物体。
- 正面图用于 SF3D 推理；侧面图和背面图只作为 Blender 修形证据。
- SF3D 适合生成整体连续网格、人物轮廓和大体服装结构，不适合可靠恢复眼睑、鼻翼、嘴唇、手指、衣服缝线等精细几何。
- 提高目标面数、细分低模或放大纹理不会自动创造缺失的解剖细节。
- 单图不能保证隐藏区域准确。输出必须标记为近似重建，不能声称是严格三视图扫描或照片级同一人物。

## 3. 阶段与质量门

### Gate 0：素材接收

必须确认：

- 正、侧、背三张图是同一个角色、相同服装、相近姿势和比例。
- 每张图片只包含一个完整人物，不使用三视图合成大图作为 SF3D 输入。
- 正面无遮挡、背景简单、人物没有被裁掉头顶或脚部。
- 记录图片分辨率；面部过小时，明确只能获得风格相近的脸，不能保证身份还原。
- 明确最终用途：网页预览、游戏角色、动画绑定或英雄级渲染。

验收：素材角色一致且正面图可独立解码。否则 `request-input`。

### Gate 1：SF3D 基线生成

1. 配置 `input=<slug>/front.png`。
2. 首次运行使用 `targetVertexCount=-1`、`remesh_option=none`，保留 SF3D 原始结果。
3. 运行 SF3D；失败时才降级 TripoSR，且产物文件名必须标明后端，禁止静默冒充 SF3D。
4. 保存原始 GLB，并导入 Blender 保存只读基线 `.blend`。

本项目命令参考：

```powershell
npm.cmd run model:check
npm.cmd run model:generate -- --Backend sf3d
```

验收：

- GLB 可解析，不是 HTML 错误页或空文件。
- 正面轮廓、身高比例、四肢数量和主要服装结构可接受。
- 必须检查正面、左右 3/4、侧面、背面；单一正面截图不能通过。
- 记录顶点数、面数、包围盒和文件哈希，作为后续“不改变基线”的证据。

### Gate 2：Three.js 原始预览

网页必须明确区分生成模型和程序化占位模型：

- URL 参数必须映射到唯一、可追踪的 GLB 文件。
- GLB 加载失败时显示醒目的 `GLB LOAD FAILED`，不得静默显示占位模型。
- 在浏览器中实测 GLB 请求的 `Content-Type` 为 `model/gltf-binary`，文件头为 `glTF`。
- 确认实际运行项目的服务根目录；修改代码和复制 GLB 前先检查 Vite/服务器进程命令行。
- 灰模材质必须应用到加载后的 GLB 节点，而不是只应用到程序化模型。
- 原始版与修形版使用相同相机、归一化规则、旋转和灯光。

验收：页面标题、场景节点和网络资产都能证明当前显示的是目标 GLB。

### Gate 3：Blender 修形策略选择

先确定用户要求的修改范围：

| 目标 | 允许的操作 | 禁止的操作 |
|---|---|---|
| 保留 SF3D 全身体型，仅修脸 | 原网格不动；独立面部补片或真正局部细分；边缘渐隐；后续烘焙 | 全身 Subdivision、全局 Smooth、全局 Remesh、全局 Decimate、重算法线 |
| 全身高模重雕 | 复制基线；Voxel Remesh；Multires；按三视图修形 | 覆盖原始基线；把重网格结果称为原 SF3D 体型 |
| 只改善网页观感 | 法线/AO 烘焙、灯光和粗糙度调整 | 用纹理或阴影声称几何细节已经存在 |

局部面部补片流程：

1. 原始 SF3D 对象保持顶点、面、法线和变换不变。
2. 从原脸表面射线采样生成密集局部补片。
3. 只在补片上建立眼窝、眼睑、鼻梁、鼻尖、唇体和下颌体块。
4. 补片边缘位移渐变为零，防止出现台阶。
5. 以独立对象保存，便于删除、替换和烘焙。
6. 导出前用断言核对原网格的顶点数和面数没有变化。

验收：开关补片时，除面部区域外的屏幕差异应为零或仅有可解释的遮挡差异。

### Gate 4：雕刻评审

评审顺序：

1. 头颅和下颌大形。
2. 眼窝、鼻体和口鼻区的一级/二级体块。
3. 眼睑、鼻翼、唇缘、耳朵等细节。
4. 衣服褶皱、缝线和配件。
5. 手、腿间、衣物穿插和背面轮廓。

每轮至少提供正面、3/4 和侧面截图，并明确：本轮改变了什么、为何改变、仍有哪些不匹配、下一动作是 `continue`、`refine-spec`、`refine-code`、`request-input` 或 `stop`。

禁止用“面数增加了”代替视觉验收。

### Gate 5：网页资产整理

1. 保留 Blender 高模作为雕刻和烘焙源。
2. 为网页制作低模/中模，不直接把数百万面雕刻模型作为正式资产。
3. 烘焙法线、AO；整理 Base Color、Roughness、Metalness，禁止把同一贴图错误复用为多个 PBR 通道。
4. 修复 UV、材质命名、透明边和错误法线。
5. 需要动画时再进行骨骼、权重、姿势和动画检查。
6. 导出 `<slug>-web.glb`，不要覆盖基线。

建议初始网页预算：角色主体 50k–150k 三角面、1K–2K 纹理；根据设备和镜头距离调整，不作为硬性上限。

验收：GLB 能加载、无控制台错误、旋转多角度不塌陷、灰模与纹理模式都可用，并在目标设备测量帧率和显存。

## 4. 本轮已验证的技术路径

- SF3D 在 RTX 4060 Ti 8GB 上可以运行，但需控制纹理和后处理显存。
- Hugging Face 的 `stabilityai/stable-fast-3d` 是 gated model，需要先在网页接受许可，再在当前终端正确设置 token。
- Windows 上 `texture_baker_cpp` 可能只有 CPU 后端；栅格化/插值可以回退 CPU，主模型推理保留 CUDA。
- SF3D 单正面图能得到真实连续网格，比基本体拼装更适合作为修形起点。
- 直接使用三视图合成图会产生噪点和错误几何，不纳入正式流程。
- Blender MCP/桥接可执行普通脚本；依赖 3D View 上下文的 Sculpt 操作可能需要 Blender UI 或改用后台稳定的对象级操作。
- 当前基线文件 `field-commander.glb` 为 8079 顶点、10060 面；这是本次保形验证基准。

## 5. 本轮失败案例与禁止复用方式

1. **全局 SIMPLE 细分后只改脸**：虽然顶点位置理论上保形，但会改变全身法线和曲面观感，不能用于“全身必须保持原样”的任务。
2. **全局 Voxel Remesh**：适合全身高模重雕，不适合保留原 SF3D 服装和体型。
3. **全局 Decimate 审查版**：会改变服装边缘和身体轮廓，不能用于严格 A/B 对比。
4. **分离五官导轨直接悬浮在表面**：只能作为雕刻参考，不能当作最终贴合细节。
5. **前向顶点高斯位移**：可做快速体块实验，但不等同于解剖雕刻，不能过度宣称完成。
6. **错误预览工程**：工作区有根项目和 `field-commander` 子项目；4175 实际服务子项目。未核对进程就修改根项目导致参数无效。
7. **静默回退程序化模型**：GLB 未加载时仍显示旧角色，造成“模型完全变样”的假象。以后加载失败必须显式失败。
8. **只看 URL 参数判断成功**：必须检查实际截图、控制台、网络响应类型和场景节点。

## 7. 推荐的下一模型执行顺序

```text
素材接收与质量门
→ 独立正面图运行 SF3D
→ 保存只读 GLB/Blend 基线及几何统计
→ 正确服务根目录中的 Three.js 原始灰模预览
→ 用户确认整体形体
→ 用侧面/背面在 Blender 校正大形
→ 用户确认修改范围
→ 局部面部雕刻或全身高模雕刻
→ 多角度对照评审
→ 低模/拓扑、法线与 AO 烘焙
→ 骨骼与权重（如需要）
→ 导出唯一命名的网页 GLB
→ Three.js 网络、视觉和性能验收
```
